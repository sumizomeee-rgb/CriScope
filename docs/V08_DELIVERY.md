# v0.8 详情、日志和资源交付

- Cue 时长回到详情一级，与已播放／播放历时分开；热接入起点未知时显示本次观测时长。去掉重复的泛化事件时间、常驻估算符号和播放中的空结束原因。时间计算口径保留在提示及技术详情。
- 三点与主题图标使用固定矢量画布居中。折叠标题改为普通按钮，箭头直接跟随展开状态；保留键盘焦点反馈，避免选中蓝底。刷新合并同步 tooltip。
- 日志仅保留页签主入口。异常与连接、原始协议（高级）分开；普通日志不再被未解释的原生内部记录淹没。
- 资源按内存、Streaming、播放用量、技术性能、响度、原生声池配置分组。标题在子项之前，同组缩进及底板；只有真正保存多个时刻的指标提供趋势。修复切换内容后的无效滚动偏移。
- SDK 补充 Cue 配置分类，不增加游戏业务接口采集点。按已匹配的播放 ID 与 Cue 名称关联：原生实例归属优先，缺失时显示“Cue 分类”，tooltip 标明 ACB 配置来源，不冒充运行时覆盖归属。仅覆盖公共 CriAtomSource 可访问的最新播放，不保证任意原生 Player 的全部并发实例。首次发送遇到断连时，元数据可能等待现有 30 秒重采样。
- Atom / FS 内存采样独立降为 1 秒；Streaming 与 Block 保持 500 ms。发布配置仍排除诊断传输、状态、Update 和回调。

## 验证

- Release 构建／自包含发布成功；137 项实际窗口检查通过，覆盖两套主题、折叠刷新、详情字段和日志分类。25 项播放语义检查通过。Release 条件编译守卫通过。
- Client Unity 重编译并重入 Play Mode，确认新版 SDK 的 raw 元数据字段已加载。采集软件接回真实 native / SDK 通道。
- 独立静音测试音源先播放再接入：时间线显示播放中，详情显示本次观测、Cue 时长 184.615 秒和三项配置分类。随后重新播放，确认新的实例使用原生 Category 归属。测试后停止并销毁临时音源、卸载临时 CueSheet。
- 实机内存采样平均约 1.02 秒，Streaming 约 0.51 秒。未将此结果表述为整体性能收益测试。
- 通过软件截图接口检查实机详情、资源页；通过窗口回归截图检查深／浅色折叠和展开的资源层级。

## 尚未解决的原生字段

原始历史抓包中，同一声池句柄出现过 num_voices=16 和 num_voices=65552；随工程附带的协议配置将此字段定义为 INT32。SDK 当前 StandardStreaming 池确认容量为 16。尚不能证明高位含义或直接截断的正确性，因此未修改协议解码，原生配置保留在“待核验”高级组，不进入容量摘要或比例计算。Streaming 摘要使用 SDK 容量。

截图和原始实验材料仅留在忽略的 .local；公共仓库不包含游戏音频资源、凭据或实机日志。
